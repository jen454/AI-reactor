# AI reactor

macOS 메뉴바에 상주하며 **AI 에이전트들의 남은 한도**를 보여주는 앱.
Claude와 Codex 각각을 게이지 하나로 보여준다 — 테두리 아크가 현재 세션 잔량,
가운데 로고, 아래 숫자.

기획은 `SPEC.md`. 번들 ID는 `dev.jinwook.aireactor`. (작업명 PaceCat에서
2026-09-19 이름을 바꿨다 — 아래의 옛 기록 중 원숭이·고양이 이야기는 그 시절 것이다.)

## 데이터 모델에서 지켜야 할 두 가지

1. **모든 수치는 잔량이다.** 두 프로바이더 모두 `used_percent` 를 주지만
   어댑터가 경계에서 한 번만 뒤집는다. 섞이면 같은 화면에서 "40%"가 서로
   반대를 가리킨다
2. **창(window)은 이름이 아니라 길이로 식별한다.** Claude는 300분·10080분
   두 개, 이 Codex 플랜은 43200분 하나뿐이고 `secondary` 는 null 이다.
   "세션 + 주간 두 개"를 가정하면 첫 번째 다른 플랜에서 깨진다

## 요구 사항

- macOS 13+
- Node 22 + pnpm
- Rust (rustup)

`cargo`가 PATH에 없으면 먼저:

```sh
. "$HOME/.cargo/env"
```

영구 적용하려면 `~/.zshrc` 에 위 줄을 추가한다.

## 개발

```sh
pnpm install
pnpm tauri dev              # 메뉴바에 아이콘이 뜬다 (Dock 아이콘 없음)
./scripts/rebuild-and-run.sh  # 릴리즈 빌드 후 새 프로세스로 실행
```

**`pnpm tauri build` 후에 `open` 만 하면 변경이 안 보인다.** 두 가지가 겹친다.

1. `open` 은 실행 중인 앱을 재시작하지 않고 활성화만 한다.
2. WKWebView가 `index.html` 을 캐시한다. Vite가 에셋 파일명에 해시를 붙이지만,
   그 해시를 *가리키는* 문서가 캐시되면 소용이 없다.

`scripts/rebuild-and-run.sh` 가 종료 → 캐시 삭제 → 빌드 → 실행을 한 번에 한다.

## Codex 데이터 경로

`~/.codex/sessions/<년>/<월>/<일>/rollout-*.jsonl` 의 `payload.rate_limits`.
**네트워크 없음, `~/.codex/auth.json` 도 안 읽는다** — 읽을 이유가 없으니
안 읽는 게 가장 안전하다.

실제 기기에서 **같은 계정의 기록이 두 형태로** 나온다.

```jsonc
// 6/8 — 한도가 있는 플랜
"rate_limits": { "plan_type": "go",
  "primary": { "used_percent": 100.0, "window_minutes": 43200, "resets_at": 1783127522 },
  "secondary": null }

// 6/10 — 구독 없음
"rate_limits": { "limit_id": "premium", "plan_type": null,
  "primary": null, "secondary": null,
  "credits": { "has_credits": false, "unlimited": false } }
```

창이 전부 null인 기록은 **놓친 게 아니라 답이다.** 더 뒤로 걸어가면 이미 없는
플랜의 숫자를 현재처럼 보여주게 된다. 그래서 `NoPlan` 으로 끊는다.

### 증분 스캔

날짜 디렉터리 이름이 zero-padded 라 이름 내림차순 = 날짜 내림차순이다.
최신 디렉터리부터 내려가다 필요한 만큼 모이면 멈춘다 — 매일 쓴 사람이
수천 개를 쌓아도 걷는 디렉터리는 몇 개뿐이다.

파일 자체는 (경로, mtime, 길이) 로 캐시한다. 롤아웃은 append-only 라
폴링마다 다시 읽을 이유가 없다.

## 빈 상태 네 가지

생김새는 비슷한데 사용자가 할 행동이 전부 다르다. 뭉뚱그리면 앱이 거짓말을 한다.

| 상태 | 의미 | 표시 |
|---|---|---|
| 로딩 | 아직 안 읽음 (`snapshots === null`) | 스켈레톤 |
| 미설치 | 이 기기에 없음 | 흐린 빈 카드, 권유 문구 |
| 만료 | 토큰 만료 | 마지막 값 흐리게 + 복구 안내 |
| **무효** | 아래 네 가지 이유 중 하나 | **숫자 숨김, 이유별 문구** |

무효는 `voidReason` 으로 이유를 구분한다. 문구가 전부 달라야 하기 때문이다 —
구독이 없는 사람에게 "CLI를 실행하세요"는 아무 쓸모가 없다.

| `voidReason` | 의미 |
|---|---|
| `noPlan` | 로그인돼 있지만 계정에 한도가 없음 |
| `noData` | 기록된 적 없음 — 한 번 실행하면 생김 |
| `windowReset` | 기록은 있는데 그 창이 이미 리셋됨 |
| `readFailed` | 읽기 실패, 캐시도 없음 |

**무효와 만료는 다르다.** 만료는 "30분 전엔 38%였다"라고 말할 수 있다.
리셋 시각이 지난 스냅샷은 그 창이 이미 갈아엎어졌다는 뜻이라 흐리게라도
보여주면 안 되는 값이다. Codex가 이 상태에 상시로 빠진다 (SPEC 9장).

**미설치에 스켈레톤을 쓰지 않는다.** 스켈레톤은 "곧 온다"는 관습이라
영영 안 오는 데이터를 기다리게 만든다.

## 메뉴바

아이콘 하나가 **"지금 신경 써야 하나?"** 만 답한다. 가장 급한 창 하나를 보여주고,
프로바이더별 내역은 클릭하면 나온다.

**프로바이더마다 아이콘을 두지 않는다.** 22pt 바에 둘을 쌓으면 각 8pt라
형태가 뭉개져서, 아이콘의 유일한 역할이 무너진다.

**숫자를 붙이지 않는다.** 게이지가 곧 수치다. 옆에 퍼센트를 쓰면 같은 말을
반복하면서 폭만 먹고, 정확한 숫자를 원하는 사람은 이미 팝오버를 여는 중이다.

| 단계 | 잔량 |
|---|---|
| level-5 | 81–100% |
| level-4 | 61–80% |
| level-3 | 41–60% |
| level-2 | 21–40% |
| level-1 | 1–20% |
| level-0 | 0% |
| expired | 만료·낡음·읽기 실패 |

**6단계로 양자화한다.** 연속 값은 16pt에서 안 보인다 — 71%와 68%의 차이를
그릴 수 없는데 그리는 척하면 정보 없이 깜빡이기만 하는 아이콘이 된다.

0%가 1–20% 아래 칸이 아니라 **자기 단계**인 이유는, "없음"과 "거의 없음"이
사람이 내릴 결정을 다르게 만들기 때문이다.

`expired` 는 패널이 전부 꺼진 링이 아니라 **빗금 친 링**이다. 패널이 전부
꺼진 채 코어만 켜진 건 "한도 없음", 빗금(+코어 꺼짐)은 "읽지 못함"이다.
같아 보이면 안 된다.

**흑백 템플릿 이미지.** macOS가 다크·라이트와 강조색에 맞춰 칠한다.
심각도는 전부 형태가 나르므로 색을 포기해도 잃는 게 없다.

### 아크 리액터형 패널 링 (모양을 다섯 번 다듬은 이유)

기본 모양은 원 둘레에 간격을 두고 배치한 **패널 5개** + 중앙 코어 점이다.
잔량만큼 위에서 시계방향으로 패널이 켜지고, 나머지는 얇은 테두리만 남는다.
100%면 5개가 다 켜져 "가동 중"인 리액터처럼 보이고, 줄어들수록 켜진 패널
수가 하나씩 준다.

여기까지 오는 데 다섯 번 손봤다.

1. **바늘 계기판.** SPEC 5장이 각도형(바늘)은 메뉴바에서 잘 안 읽힌다고
   경고했고 실측하니 맞았다 — 바늘만 그렸을 때 0%와 20%가 **1760px 중 65px**
   차이였다. 신호가 아니라 미동이라, 스윕을 160°로 넓히고 잔량만큼 차오르는
   굵은 호를 더하고 바늘을 가장 무겁게 그려서 겨우 넘겼다.
2. **연속 충전 링.** 아크 리액터 요청을 받고, SPEC 5장이 바늘과 같은 문단에서
   도넛형도 경고했다는 걸 확인한 뒤 같은 방식으로 다시 쟀다. 360°를 다 쓰므로
   한 단계가 72°(바늘의 32°보다 넓다)라 legibility는 통과했지만, 연속으로
   차오르는 모양이라 "패널이 몇 개 켜졌나"는 안 보이고 로딩 스피너처럼 읽혔다.
3. **패널 링.** 세그먼트 바·바나나 개수에서 이미 확인한 "개수형은 단계당
   변화가 크다"는 성질을 원형으로 옮겼다. 처음 26° 간격으로 만들었더니
   **패널 사이 틈이 아예 안 보였다** — `Canvas::arc` 가 `width` 를 반지름으로
   그대로 넘기는 버그가 있어서, 굵기 4.2로 지정한 게 실제로는 지름 8.4로
   그려졌고 이웃 캡끼리 겹쳐 5개가 하나의 링으로 뭉쳤다. 근본 원인(버그)을
   고치고 나서야 간격이 제대로 보였다.
4. **더 두껍게.** "아이언맨 아크 리액터처럼"이라는 요청을 받고 `ON_STROKE`
   를 4.2 → 7.0으로 올렸다. 이때 간격도 같이 늘려야 했다 — 캡 반지름이
   굵어진 만큼 이웃 캡이 다시 서로 먹어치우기 시작하기 때문이다. 간격을
   26° → 40°로 넓혀서 순가시 간격(캡 소비를 뺀 실제 보이는 틈)을 1.7px에서
   2.8px로 유지했다. 코어도 2.4 → 3.4로 키워 두꺼워진 패널들 사이에서 묻히지
   않게 했다.
5. **지금 — 각진 모서리.** "더 기계적으로, 모서리가 각지게"라는 요청을 받고
   `Canvas::arc`(원형 스탬프를 이어 붙인 스트로크, 끝이 둥근 알약 모양)를
   `Canvas::annular_wedge`(두 반지름과 두 각도 사이를 실제로 채우는 사다리꼴)
   로 바꿨다. 끝이 캡이 아니라 직선으로 잘리므로 **캡이 간격을 갉아먹는
   문제 자체가 사라졌다** — 그래서 간격을 40° → 14°로 다시 줄일 수 있었고,
   패널 폭은 오히려 32°에서 58°로 넓어졌다(간격이 줄어든 만큼 패널이 커짐).

다 채워진 링이 빈 링보다 잉크 반지름이 조금 더 넓다는 것도 실측으로 확인했다
— 켜진 패널이 꺼진 패널보다 굵어서 생기는 자연스러운 차이다. 다만 `render()`
는 항상 44×44 고정 버퍼를 반환하므로 macOS가 잡는 아이콘 크기 자체는 레벨과
무관하다. 이웃 아이콘이 밀릴 실제 위험은 없고, `the_canvas_footprint_never_changes`
가 바로 그 제약(캔버스 크기 불변)을 검증한다.

아이콘 팩을 새로 만들 때도 `neighbouring_levels_are_distinguishable` 과
`every_level_looks_different` 를 통과해야 한다.

### 애니메이션 없음

단계가 바뀔 때만 다시 그린다. 드라이버는 초당 한 번 깨어나 뷰를 비교하고,
같으면 아무것도 하지 않는다. 프레임 하나 갱신이 3.3ms라 상시 애니메이션은
CPU 5.5%였다 (SPEC 12장).

### 지금은 플레이스홀더다

`art.rs` 가 기본 팩(아크 리액터 패널 링)을 코드로 그린다. **이건 아이콘 팩
시스템이 아니고 거기로 자라서도 안 된다.** 마일스톤 6에서 `manifest.json` +
SVG 7장으로 바뀌고, 살아남는 건 `Level` 뿐이다.

## 폴링 주기

| 팝오버 | 실제 조회 | 비고 |
|---|---|---|
| 닫힘 | **3분** | 트레이 아이콘만 쓰므로 대략 맞으면 된다 |
| 열림 | **30초** | 여는 순간은 즉시 조회 |

SPEC 5장은 닫힘 60초 / 열림 10초를 요구했지만 실측하며 둘 다 바뀌었다.

**열림 30초.** 10초로 실측했을 때 **약 7회 요청 만에 429**가 왔다. 이
계정은 `claude` CLI와 CI가 같이 쓰므로 우리 폴링이 사용자의 실제 작업과
경쟁한다. 30초는 패널을 보는 사람 입장에서 체감이 같고(숫자가 천천히
움직인다) 한도 아래에 머문다.

**닫힘 3분** (2026-09-17 결정). 팝오버를 열면 언제나 즉시 재조회하므로, 이
주기는 **메뉴바 아이콘 자체의 최신성**에만 영향을 준다 — 팝오버를 열었을 때
보는 숫자는 이 값과 무관하게 항상 방금 것이다. 3분이면 시간당 20회로,
5시간 창 기준 최대 지연 오차는 1%다.

`schedule.rs` 는 `thread::sleep` 대신 조건변수를 쓴다. 고정 sleep은 중간에
끊을 수 없어서, 팝오버를 열어도 남은 시간만큼 묵은 숫자로 기다려야 하기
때문이다. 마감시각을 `직전 폴 + 현재 주기` 로 매번 다시 계산하므로 열면
당겨지고 닫으면 늘어난다 — 잠깐 열었다 닫아도 빠른 폴링이 남지 않는다.

## TLS

`ureq` + **native-tls**. macOS 가 이미 Security.framework 를 링크하므로
rustls 와 루트 인증서 사본을 번들할 이유가 없다 — 분당 GET 한 번에 0.5MB 다.

주의: ureq 는 native-tls 만 켜도 기본 provider 를 rustls 로 고르고 첫 https
요청에서 **패닉**한다. `TlsConfig::builder().provider(NativeTls)` 를 명시해야
한다. 그 패닉이 폴러 스레드를 통째로 죽였던 적이 있어서, 지금은 provider
호출을 `catch_unwind` 로 감싼다 — 패닉도 그냥 실패의 한 종류로 취급해
`stale` 로 떨어뜨린다.

## 한도 엔드포인트

```
GET https://api.anthropic.com/api/oauth/usage
Authorization: Bearer <access token>
```

```json
{ "five_hour": { "utilization": 63, "resets_at": "2026-09-11T04:00:01.028710+00:00" },
  "seven_day": { "utilization": 34, "resets_at": "..." } }
```

문서화된 공개 API가 아니다. 실측으로 확인한 두 가지 함정:

- **`utilization`은 이름과 달리 이미 퍼센트(0–100)다.** 0~1 분수가 아니다.
  CLI 코드에 보이는 `utilization * 100`은 파이프라인 뒤쪽의 정규화된 내부
  구조체를 다루는 것이지 이 응답이 아니다.
- **`resets_at`은 RFC 3339 문자열이다.** Unix 초도 받아들이도록 해뒀다.

범위를 벗어난 값이 오면 경고를 찍는다. clamp가 단위 변경을 조용히 삼키면
"한도 100%"라는 확신에 찬 거짓말이 나오기 때문이다.

`anthropic.rs` 가 이 엔드포인트를 아는 유일한 파일이다. 바뀌면 거기만 고친다.

## 개발 중 키체인 허용 창

Rust를 리빌드할 때마다 "AI reactor가 키체인의 기밀 정보를 사용하려고 합니다" 창이
뜬다. **정상이다.** 없애려면 Apple Development 인증서가 필요하다.

macOS는 키체인 항목 접근을 두 가지로 따로 검사한다.

1. **ACL requirement** — `scripts/setup-dev-cert.sh` 로 만든 자체 서명 인증서
   덕분에 `identifier "dev.jinwook.aireactor" and certificate root = H"..."` 로
   고정돼 있다. 리빌드해도 유지된다.
2. **partition list** — 이건 별개다. Team ID가 있는 앱이면 `teamid:...` 로
   기록되지만, 자체 서명 인증서에는 Team ID가 없어서 macOS가 `cdhash:` 를
   기록한다. cdhash는 빌드마다 바뀌므로 매번 다시 묻는다.

무료 Apple ID로 Xcode에서 Apple Development 인증서를 받으면 Team ID가 생겨
완전히 해결된다. 그때까지는 리빌드당 클릭 한 번이다.

## 주의

`~/.claude/` 는 **읽기 전용**이다. 토큰 갱신 엔드포인트는 절대 호출하지 않는다
(자격증명의 소유자는 `claude` CLI 하나뿐이다).

이 규칙은 세 겹으로 강제된다.

1. `credentials/parse.rs` 는 **refreshToken 필드를 아예 갖지 않는다.** serde가
   모르는 키를 버리므로 refresh token은 파싱 경계를 넘지 못한다. 갱신 요청을
   조립하려 해도 재료가 없어서 컴파일이 안 된다.
2. `AccessToken` 은 `Serialize` 를 구현하지 않는다. 따라서 `#[tauri::command]`
   반환값에 넣을 수 없고, 토큰이 webview로 넘어갈 수 없다.
3. `AccessToken` 은 `Debug` 를 파생하지 않고 `<redacted>` 를 출력하며,
   drop 시 zeroize로 메모리를 덮어쓴다.

키체인 프롬프트는 **팝오버를 처음 열 때** 뜬다. 실행만으로는 뜨지 않는다.
숨겨진 Tauri 창도 webview는 살아 있어서 React 타이머가 계속 도는데, 그대로 두면
앱을 켜자마자 아무 맥락 없이 허용 창이 튀어나온다. 그래서 Rust가
`popover-visibility` 이벤트를 쏘고 프론트는 팝오버가 보일 때만 폴링한다.

키체인은 매번 읽지 않는다. `CredentialStore` 가 메모리에 캐시하고, 만료가
임박했을 때만 다시 읽는다. 사용자가 키체인 접근을 거부하면 **지수 백오프**가
걸린다 — 1분 → 2분 → 4분 → … 최대 1시간. 영구 래치가 아니라 백오프인 이유는
새로고침 버튼(팝오버 하단)이 폴러를 경유하는 자동 헬스체크로 바뀌면서, 거부를
사용자가 직접 풀어줄 수동 경로가 없어졌기 때문이다 — 실수로 거부했다면 1분
안에 스스로 회복해야 한다.
